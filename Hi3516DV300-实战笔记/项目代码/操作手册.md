# Hi3516DV300 摄像头项目 · 操作手册

> 从零部署到看到画面、日常维护、改代码更新的完整操作流程。
> 所有命令均实测过（2026-11-06）。环境变化时（换网络）注意改 IP。

## 0 · 环境拓扑

| 角色 | IP | 说明 |
|---|---|---|
| 板子 | 192.168.1.20（静态） | telnet 23 / RTSP 554 |
| 开发 VM（Ubuntu） | 192.168.142.25 | lmo/123456，SSH；tftp 服务器，源码在 `~/hisi/Hi3516CV500_SDK_V2.0.2.0/` |
| PC（Windows） | 任意 | VLC 播放器、tftp 客户端不需要 |

> 网络要求：板子掩码 **255.255.0.0**（/16），网关 192.168.3.1（公司）/ 192.168.1.1（家）——S99rtsp 会自动探测补网关。
> 板子 IP 变了只改下面命令里的 IP；VM IP 变了改 tftp 命令里的 IP 和 tools/*.py 里的地址。

## 1 · 首次部署（出厂固件 → 跑起来）

板子出厂固件已含 GC2053 sensor 库和 ko（S00devs 里 `./load3516dv300 -i -sensor0 gc2053` 开机自动加载）。需要装的只有三样：**守护脚本、sample_venc 二进制、NNIE 模型**。

```sh
# ── 在 PC 上执行（tools/ 目录下，python 需装 paramiko/telnetlib）──

# 1. 板子进 /mnt（tmpfs，掉电不丢根分区）
#    telnet 192.168.1.20，账号 root（无密码）
mount -t tmpfs -o size=48m none /mnt        # 若未挂
mkdir -p /mnt/nnie

# 2. 从 VM tftp 下载模型（大文件，串口粘贴一条一条来）
cd /mnt/nnie && tftp -g -r inst_ssd_cycle.wk -l /mnt/nnie/inst_ssd_cycle.wk 192.168.142.25

# 3. 从 VM tftp 下载 sample_venc 二进制并装进 /usr/bin
cd /mnt && tftp -g -r sample_venc -l /mnt/sample_venc 192.168.142.25
cp /mnt/sample_venc /usr/bin/sample_venc && chmod +x /usr/bin/sample_venc   # chmod 必须！tftp 下载件是 644

# 4. 装守护脚本（PC 上把 board/ 下两个文件传上板后）：
cp S99rtsp /etc/init.d/S99rtsp && chmod +x /etc/init.d/S99rtsp
cp S80network /etc/init.d/S80network && chmod +x /etc/init.d/S80network

# 5. 启动
/etc/init.d/S99rtsp start
```

**⚠️ 禁忌**：`/etc/init.d/` 里**不要留任何备份文件**（`xxx.bak` 会被 rcS 当启动脚本执行，血泪教训见第 11 篇）。

## 2 · 日常操作

### 2.1 启动/停止（脚本三态）

```sh
/etc/init.d/S99rtsp start     # 启动（带守护线程，崩了 3s 自动拉起）
/etc/init.d/S99rtsp stop      # 停止（先 TERM 优雅退出让 VB 池清理，10s 后才 -9 兜底）
/etc/init.d/S99rtsp restart   # 重启
```

**开机自动启动**：装好 S99rtsp 后每次上电自动跑，无需手动。**检测模型重启会丢**（/mnt 是 tmpfs），重启后检测自动降级为"只取帧不画框"，要恢复就重新 tftp 模型（§1 步骤 2）。

### 2.2 看画面（VLC）

```
VLC → 媒体 → 打开网络串流 → rtsp://192.168.1.20/live
```

- H.264 1080p，UDP/TCP 自动协商；画面上有**时间水印**（layer2）和**人形红框**（layer1，检测到才画）
- 没有红框 ≠ 故障：先确认模型在位 `ls /mnt/nnie/inst_ssd_cycle.wk`，再看日志有没有 `persons=` 行

### 2.3 状态自检（一分钟四板斧）

```sh
ps | grep sample_venc | grep -v grep          # ① 进程在不在
netstat -ln | grep 554                        # ② RTSP 监听在不在
tail -5 /mnt/sample_venc.log                  # ③ 日志（找 [DET] infer / 报错）
cat /proc/umap/venc | grep -A2 "VencInt"      # ④ 编码中断在涨（两次执行比数值）
```

## 4 · 改代码更新到板子（完整循环）

```sh
# ① VM 编译（§3）
# ② VM 放到 tftp 目录
cp ~/hisi/.../sample/venc/sample_venc /srv/tftp/sample_venc_new

# ③ 板端停服务（stop 会优雅清理 VB 池，可反复）
/etc/init.d/S99rtsp stop

# ④ 板端下载替换（tmpfs 落地再 cp，jffs2 写大文件要耐心）
cd /mnt && tftp -g -r sample_venc_new -l /mnt/sample_venc_new 192.168.142.25
cp /mnt/sample_venc_new /usr/bin/sample_venc && sync && chmod +x /usr/bin/sample_venc

# ⑤ 重启验证
/etc/init.d/S99rtsp start
sleep 10 && tail -5 /mnt/sample_venc.log && netstat -ln | grep 554
# VLC 复验 rtsp://192.168.1.20/live
```

## 6 · 快速故障对照

| 现象 | 先查 | 处理 |
|---|---|---|
| VLC 打不开 | §2.3 的 ①② | 进程死→看日志；监听没有→start |
| `start` 报 `SetConf failed` rc=255 | VB 池残留（只有 -9 强杀才这样） | `reboot` 一次；新版脚本已带 TERM 优雅退出，连续 10 次会自动 reboot |
| 进程反复崩 | 日志 `tail -20 /mnt/sample_venc.log` | 通常是模型路径或 VB 池参数问题 |
| 有画面没红框 | `ls /mnt/nnie/` + 日志找 `luma-only` | 模型丢失，按 §1 步骤 2 重传 |
| 有画面水印不动 | `date` 看板子时间 | 等 ntpd 对时（S99rtsp 后台自动做）；断网则时区/时钟问题 |
| 画面黑/绿屏 | `cat /proc/umap/mipi_rx` | DETECT 有 1920×1080 = 底层正常；全 0 = 硬件/驱动层（见第 13 篇排障表） |
| telnet 连不上 | 网口灯、ping 192.168.1.20 | 检查 PC 掩码 /16；S90telnet 在不在 /etc/init.d/ |

## 7 · 架构一图流（改哪里影响什么）

```
S00devs → load3516dv300（ko 层，闭源，一般不动）
   ↓
sample_venc 主程序（venc_sample_venc.c）
   ├─ VB 池三池 ────── 改池大小 → 重编译部署
   ├─ VPSS 三通道 ──── chn0 主码流 1080p / chn1 子码流 / chn2 给 NNIE 300×300
   ├─ RTSP 服务器 ──── 实现在 common_sample_comm_venc.c（端口 554，会话 /live）
   ├─ OSD 水印 ─────── osd_test.c（layer=2）
   ├─ NNIE 检测 ─────── nnie_detect.c（取帧/推理/红框 layer=1）
   └─ 模型 ─────────── /mnt/nnie/inst_ssd_cycle.wk（tmpfs，重启丢）
```
