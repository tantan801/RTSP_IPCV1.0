## 1. 开机自动加载 sensor（S00devs）

### 为什么要改

`/etc/init.d/S00devs` 里那句 `load3516dv300` 决定了 **sys_config.ko 加载时告诉 ISP 用哪个 sensor**。原脚本没写 `-sensor0`，内核默认走 imx335，于是：

```
GC2053 init succuss!            ← 用户态库自己成功（假象）
cmos_fps_set Not support Fps: 0.000000
VENC QueryStatus 0xa0088010 刷屏
```

根因不是 GC2053 坏了，而是**ISP 初始化链路里 fps 传了 0**，整条 VI 起不来。

### 正确内容

`/etc/init.d/S00devs` 第 13 行：

```sh
./load3516dv300 -i -sensor0 gc2053 -osmem 128 -total 1024
```

参数含义：

| 参数 | 含义 |
|---|---|
| `-i` | insmod 所有 ko |
| `-sensor0 gc2053` | sensor0 用 gc2053（字符串传给 sys_config.ko） |
| `-osmem 128` | 操作系统可用内存 128MB（实测 MemTotal ≈ 120,980 kB） |
| `-total 1024` | DDR 总量 1GB，其余全部划给 MPP 的 MMZ |

> 注意：`-osmem` 是给 Linux 的，剩下的才是媒体内存池（MMZ）。OS 只有 120MB 意味着 **tmpfs 不能开太大**（见第 5 篇）。

### 1.1 内存是怎么分的（决定你能开多大 tmpfs）

```
DDR 1GB（-total 1024）
├─ 128MB  → Linux 内核 + 用户态（-osmem 128）
│            实际 MemTotal ≈ 120,980 kB（内核自己又吃掉几 MB）
└─ 896MB  → MMZ（媒体内存区，MPP 独占）
             ├─ VB 池（图像帧缓存）
             ├─ VENC 码流缓冲
             └─ ISP 中间缓冲
```

三个直接推论：

| 现象 | 原因 |
|---|---|
| `free` 只看到 121MB，不是 1GB | 大头被 MMZ 拿走了，正常 |
| tmpfs 最多只能挂 48MB 左右 | 它是从 Linux 那 121MB 里分的，开太大系统就 OOM |
| 码流写 tmpfs 不影响 MMZ | 两个池物理隔离，互不抢占 |

查 MMZ 用量：

```bash
cat /proc/media-mem          # MMZ 总大小、已用、剩余（最直观）
cat /proc/umap/vb            # VB 池每块的 size / count / free
```

### 验证

```bash
dmesg | grep sensor0        # 期望：sensor0: gc2053
cat /proc/umap/vi | grep -A2 "VI PIPE STATUS"
```

## 3. telnetd：远程 shell

```bash
# 串口里执行
telnetd -l /bin/sh &
```

开局一条命令就有一个免密码 root shell，PC 上 `telnet 192.168.1.20` 即可。

**重启会丢**（没固化）。要固化：

```sh
cat > /etc/init.d/S81telnetd <<'EOF'
#!/bin/sh
telnetd -l /bin/sh
EOF
chmod +x /etc/init.d/S81telnetd
```

> 安全提醒：这只是实验室环境。产品化要么关掉，要么加认证/走 SSH。

## 4. 文件传输：tftp 双向

| 方向 | 命令 |
|---|---|
| VM → 板子（板子拉） | 板端：`tftp -g -l 本地名 -r 远端名 192.168.1.103` |
| 板子 → VM（板子推） | 板端：`tftp -p -l 本地名 -r 远端名 192.168.1.103` |

VM 端服务（tftpd-hpa）：

```bash
# /etc/default/tftpd-hpa
TFTP_OPTIONS="--secure --create"     # --create 允许上传新文件
# 目录
mkdir -p /srv/tftp && chmod 777 /srv/tftp
```

实测速率约 100KB/s 量级（busybox tftp 块小），传 10MB 需要几分钟——**大文件优先考虑 NFS 或直接不落地**。

### 4.1 顺手补：嵌入式常见文件系统怎么选

这是第 5 篇踩坑的理论背景。选错文件系统，写码流就能把整条链路压死。

| 文件系统 | 典型介质 | 特性 | 适合 |
|---|---|---|---|
| **jffs2** | NOR / 小 NAND | 日志结构、挂载慢、**接近满时 GC 会让写延迟飙到秒级** | 几十 MB 的只读根分区 |
| **ubifs** | NAND | 比 jffs2 快得多，支持大容量、压缩 | 现代 NAND 的根分区 |
| **ext4** | eMMC / SD | 成熟稳定、有 journal、随机写好 | 录像盘、大容量存储 |
| **vfat** | SD / U 盘 | 跨平台，无日志，断电易损坏 | 和 PC 交换文件 |
| **tmpfs** | RAM | 内存盘，**最快**，断电即失 | 临时码流、调试 |
| **NFS** | 网络 | 不占本地空间，依赖网络稳定 | 开发阶段最省事 |

**两条硬规则**：

1. **码流永远不写 jffs2 根分区**（用 tmpfs / SD / NFS / 直接推流）
2. 产品要断电可靠，录像必须放 ext4 + 异常断电后 `fsck`，vfat 会掉文件系统

## 5. 用 python 直连 telnet 做自动化（本次效率关键）

板子只有串口 + telnet，串口在一个窗口里跑交互程序时就没法干别的。用 python socket 直连 23 端口可以开多路，还能脚本化。

### 5.1 基础封装

```python
import socket, time, re

def connect(host='192.168.1.20'):
    s = socket.create_connection((host, 23), timeout=5)
    s.settimeout(1.0)
    return s

def clean(b):
    # 去掉 telnet 的 IAC 协商字节，否则输出里全是乱码
    return re.sub(rb'\xff[\xfb\xfc\xfd\xfe].', b'', b).decode(errors='replace')

_n = [0]
def run(s, cmd, wait=4.0):
    """发命令并等到标记回显，返回输出"""
    _n[0] += 1
    marker = 'ZD%dR' % _n[0]
    s.sendall((cmd + '; echo ' + marker + '\n').encode())
    out, end = b'', time.time() + wait
    while time.time() < end:
        try:
            d = s.recv(65536)
            if not d:
                break
            out += d
            if marker.encode() in out:      # 看到标记就可以提前返回
                end = min(end, time.time() + 0.4)
        except socket.timeout:
            pass
    return clean(out)
```

### 5.2 两个必须知道的坑

**坑 A：终端回显会让 marker 立刻命中**

没关回显时，命令行本身就会被回显回来，里面就含 marker 字符串，导致 `run()` 提前返回、命令其实还在跑。

```python
run(s, "stty -echo", 1.5)   # 第一件事：关回显
time.sleep(0.3)
try: s.recv(65536)          # 清掉残留
except socket.timeout: pass
```

**坑 B：`cmd &` 后台任务在这个 shell 里不生效**

实测 `(printf ...; sleep 45; ...) | ./sample_venc 0 > log 2>&1 &` 发过去，**日志文件都没创建**，进程也没起来（原因未深究，可能是 busybox 交互 shell 的作业控制）。

解法：**开两个连接**——一个前台跑占用终端的程序，另一个查 `/proc`。

```python
sa = connect(); run(sa, "stty -echo")      # 控制/查询
sb = connect()
sb.sendall(b"cd /mnt && ./sample_venc 0 > /tmp/log 2>&1\n")   # 前台跑
time.sleep(14)
print(run(sa, "cat /proc/umap/vi"))        # 另一个会话随便查
```

### 5.3 给交互式 sample 自动喂输入

`sample_venc 0` 会依次问：gop 模式（`0`=NORMALP）、rc 模式（`c`=CBR）、最后"按两次回车退出"。用管道喂：

```bash
cd /mnt && ( printf '0\nc\n'; sleep 20; printf '\n\n' ) | /root/sample_venc 0 > /tmp/vl.log 2>&1
```

含义：先答两个问题 → **录 20 秒** → 补两个回车让它干净退出。

> 注意顺序：`printf '0\nc\n'` 是先 gop 还是先 rc 要按源码实际顺序来。本 SDK 里先 `GetRcMode()` 再 `GetGopMode()`，所以要喂 `c` 在前？——实测上面这条能用，因为两个 `getchar` 循环会跳过不匹配字符并重问，容错性比想象的好。**不确定就开个会话手动跑一次，看提示顺序。**
